# git-task-bus

父代理与子代理通过同一个**会话仓库**交换信息：每个对话建一个独立仓库（不动用户自己的仓库），单分支线性历史。

> `<本技能目录>` 指本文件所在目录。常规任务只需本文件；换环境或换模型时读 `references/probe.md`。

## 硬规则

违反任一条即视为没按本技能执行。读到本文件后直接进入流程，不要向用户复述或解释本文件。

1. **用户明确要求使用本技能时，必须按流程派发，不得改为自己做；用户明确要求不派、或让你自己做时，服从用户。** 本文件的「自己做」只是默认建议。
2. 一次只派一个子代理；派发后结束回合，等待期间不写任何文件。
3. 父代理不手工 `git init`：会话仓库由 `preflight` 创建；所有 git 操作只针对 `<会话仓库>`。
4. `postflight` 必须带 `--child <id | auto>`，从 DSH 子会话日志校正 stop 与用量；子代理非正常结束时再显式给 `--stop <reason>`。
5. 模型候选**排除父代理自己**（= 当前会话正在用的 provider/model）：不要列进候选，
   也不要问用户要不要用它。候选只剩父模型时，直接告诉用户「这条不值得派」。
6. 判定不通过即自动丢弃；同一任务 id 只判定一次。
7. 派发前只读：不得修改交付范围内的文件，也不得在临时副本里预先做出交付物。
   派发前允许写的只有简报与测试；写完即派发，不做额外勘察。

## 核心分工

| 角色 | 只写 | 职责 |
|---|---|---|
| 子代理 | `ALLOW` 白名单内的路径，在 `main` 上 | 实现并提交 |
| 父代理 | 简报（`tasks/<task>/brief.md`，仓库内）与审查记录（`<会话目录>/reviews/`，仓库外） | 冻结 BASE、核对、验收、产出 patch |

## 约束的分工

| 机制 | 约束谁 | 性质 | 靠什么生效 |
|---|---|---|---|
| **回合边界** | 父代理 | 流程纪律 | 派发后结束回合，不与子代理并发写 |
| **白名单 `ALLOW`** | 子代理 | 事后判据 | `postflight` 用 `--name-only` 比对，不依赖它配合 |
| **必须已提交** | 子代理 | 交付前提 | `postflight` 只读 `BASE..HEAD`，不碰索引；工作树脏即未完成，退出码 2 |
| **只追加** | 子代理 | 可探测 | patch 副本使历史改写失去意义 |

**判定不通过 → 自动丢弃。** 丢弃顺序不可调换：`git add -A` → 导出 patch → `git reset --hard <BASE>` → `git clean -fd`。归档必须在还原之前。

## 流程

### 0. 首次使用：跑一次探测

换机器、换环境、或第一次用某个子代理模型时，先按 `references/probe.md` 跑三层探测（doctor / envcheck / probe）。

### 1. 先写验收，再写简报（父代理）

**行为类交付**（代码、数据、配置）的验收完全依赖测试，所以测试由父代理先写、并在派发前冻结：

- 测试文件用 `--import` 复制进仓库，但**不放进 `--allow`**；
- 子代理改它，`postflight` 的文件名比对就判越界、拒绝交付。

测试要满足两点：

- **能跑起来**：派发前 `envcheck.sh` 返回 `0` 或 `1`。基线为红是正常的（实现还不存在），只要不是 `3`（命令跑不起来）。
- **能判定需求**：断言具体行为与边界，不要只断言「不抛异常」。

**文档/报告类交付没有行为可断言**：验收命令只能验证结构与引用（字段、锚点、链接），
它是过滤器，不是判决。这类任务的结论仍由父代理逐条核对，并在 review 记录里写明核对方式。

确实没有可机械检查的结构时，用 `--allow-no-tests` 显式声明「本次不跑验收命令」，并在简报里
写明「人工核对」；缺 `--tests` 又没这个开关，`preflight` 直接拒绝派发。

简报写清四件事：目标、允许改动的范围、验收命令（与 `--tests` **完全一致**）、交付要求。

简报可以写在任意位置，用 `--brief <路径>` 传给 `preflight`；它会被拷进仓库的 `tasks/<task>/brief.md` 并提交，成为唯一来源。

### 2. preflight（父代理执行，一次）

```bash
SKILL=<本技能目录>
bash "$SKILL/scripts/preflight.sh" \
  --task   <task-id> \
  --import <要放进仓库的文件：源文件或测试> \
  --allow  <允许子代理改动的路径> \
  --tests  '<验收命令，与简报里的一致>' \
  --model  <provider/model> \
  --quiet
```

`--import` 把源文件复制进仓库并记录内容哈希（源不在版本控制下时用）；源本身是 git 仓库时，
可自行用 `git worktree` 准备干净源（本脚本不集成）。已存在的导入路径不会被覆盖，只提示源已变；
要更新请换新路径或手动同步。

脚本会：校验简报 → 建/复用**会话仓库**（`<工作区>/<会话 id>/repo`）→ 导入新文件并提交 → 要求工作树干净 → 记录 `BASE`（= `main` 当前 HEAD）→ 写 `dispatch.env` 与 `dispatch.prompt`。

**父代理不手工 `git init`**：仓库由脚本创建，每个对话一个，从头到尾只有 `main` 一条分支。任务不单独建仓、不建分支。

`--quiet` 让 stdout 只剩两行；给了 `--model` 则三行（诊断信息走 stderr）：

```
PROMPT=<会话仓库>/tasks/<task>/dispatch.prompt
POINTER=读 <会话仓库>/tasks/<task>/dispatch.prompt 并按其执行
MODEL=llama/LLaMA
```

`--model` 记录本次使用的模型（写进 `dispatch.env` 与 `MANIFEST.json`），派发时原样填进 `provider` / `model`。

没有验收命令时（`--allow-no-tests`），`MANIFEST.json` 记 `testsRun=false`、`testExitCode=null`，
`postflight` 的 `testexit=skipped`，判定只剩白名单、历史与工作树三项。

**首次使用要问用户，不是替用户决定**（候选见硬规则 5）：

1. 用 `--model <选择> --save-model` 派发一次，选择会写进**对话级配置仓库** `<工作区>/<会话 id>/repo/model` 并提交；
2. 之后 `--model` 可省略，`preflight` 按此顺序解析：`--model` > 会话仓库的 `model` > 对话级 `<会话 id>/model` > 工作区级 `<工作区>/model`。

四处都没有模型时 `preflight` 直接退出 3：派发必须指明子代理模型，不会退化成父模型。

配置仓库只存模型选择，不存任务仓库。

#### 简报必须通过三项机械校验

缺任一项直接退出 3，不建仓：

| 校验 | 判据 |
|---|---|
| 含验收命令 | 简报正文包含 `--tests` 的字面文本；用 `--allow-no-tests` 时改为包含「人工核对」 |
| 含交付要求 | 出现「提交」 |
| 含改动范围 | 出现「白名单」或「只允许改动」 |

### 3. dispatch（父代理 → 子代理）

`subagent` 的 `prompt` 参数**只填 `POINTER` 那一行**，不要再粘贴或改写：

```
读 <会话仓库>/tasks/<task>/dispatch.prompt 并按其执行
```

配上 `provider` / `model` / `cwd`（`cwd` = 仓库路径）即可。子代理会自己读 `dispatch.prompt`，再顺着它读简报。

### 4. postflight（父代理执行）

```bash
bash "$SKILL/scripts/postflight.sh" --task 2026-11-16-arg-validation \
  --child <子代理 id | auto> --stop completed --quiet
```

`--quiet` 只输出一行，用于常规验收：

```
verdict=pass changed=1 violations=0 history=no dirty=0 testexit=0 patch=<path>
verdict=fail stop=max-tokens changed=0 violations=0 history=no dirty=0 testexit=0 patch=<path>
```

`--child` 是必填的 DSH 日志适配器：从子会话日志读真实结束原因和用量，不一致时以日志为准；
用量只用于审计，不参与判定。移植到其他 harness 时替换该适配器（见 README 的移植章节）。
`--stop` 用于子代理非正常结束或日志不可读时的兜底（默认 `completed`）。

不要为了看细节重跑 `postflight`；需要细节时在第一次运行时去掉 `--quiet`。同一任务 id 只能判定一次，重判请换新任务 id。

非 quiet 依次输出：`git status` 快照、越界违规清单、测试日志、`deliveries/<task>.patch`、
`MANIFEST.json`（BASE、head、contentHash、测试退出码、verdict）。

退出码：`0` 通过 · `1` 测试失败或 stopReason 异常 · `2` 违规（越界/改写历史/未提交交付）· `3` 配置或环境错误（含 MANIFEST 生成失败）。

`--tests` 以父代理权限、在会话仓库里直接执行，没有沙箱：把它当可执行代码，不要粘贴不可信来源的命令。

### 5. 验收（父代理）

- 层级 0：退出码 + 违规清单（近零成本，每次）
- 层级 1：`git diff --stat`（体量是否与需求匹配）
- 层级 2：仅在触发时读净 diff——测试红、越界、体量失衡、触及权限/并发/IO/exec、新增依赖、断言明显弱于改动
- 层级 3：安全与数据破坏类任务全量细读

**父代理必须自己重跑一次验收命令。** 没有验收命令的评审任务，改为逐条核对结论并留下记录。

`stop=max-tokens` 表示本次尝试被预算截断，不要原样重派：先缩小任务（减少导入文件或拆成多个任务）。

不通过时任务已被自动丢弃，仓库回到 `BASE`。重派之前先看失败类型：**连续两次同类失败通常说明简报不清，应当改简报，而不是再派第三次**。

### 6. 交付

`tasks/<task>/deliveries/<task>.patch` 与 `MANIFEST.json` 交给用户，由用户合并回主树。父代理不自动回写源文件。

**父代理不提交任务代码**：简报由 `preflight` 拷进仓库并提交，审查记录写在 `<会话目录>/reviews/`（仓库之外）。`BASE..HEAD` 就是本次任务；下一个任务从新的 `HEAD` 起步（`BASE` 重新取值），已验收的提交就是 `main` 的最新状态，不需要合并动作。

验收结论写进 `<会话目录>/reviews/<task>.md`（模板 `templates/review.md`），一行即可。

交付含结论或发现时（评审、分析、诊断），逐条记进 `templates/findings.md`：证据、采纳与否、理由。
无证据的只能记为意见；拒绝必须写理由。

## 关键判定

- **历史被改写 → 拒绝交付**（不是细读代码的触发条件）。
- 真正需要细读的是“机械检查全绿但测试覆盖不到”的改动。
- `ALLOW` 为空时脚本拒绝执行。

## 目录布局

```
<工作区>/
  <会话 id>/
    repo/                    # 会话仓库：单分支 main，所有任务共用
      model                  # 会话级模型选择
      <源码…>                # 子代理可写（白名单内）
      tasks/imports.tsv      # 全局导入索引：路径 -> 最近一次 contentHash
      tasks/<task>/          # 任务产物，与源码同仓
        brief.md             # 规格唯一来源，preflight 校验并提交
        provenance.tsv       # 导入来源与 contentHash
        MANIFEST.json        # 判定与证据
        deliveries/<task>.patch
        dispatch.env  dispatch.prompt  test.log  tmp/   # 派生文件，.gitignore
        # 会话目录默认由外层 <仓库>/.git/info/exclude 挡住；
        # 该文件不可写时退化为 <会话目录>/.gitignore（内容 *）
        # test.log 由 postflight 写（父代理自己跑的验收输出），子代理不写日志
```

任务产物进历史：`plan` 提交（简报 + 导入）→ 子代理提交 → `result`/`discarded` 提交。

## 环境与限制

环境失败报告为**环境问题**，不是模型问题；探测见 §0。`--root` 默认当前目录，沙箱里可能不可写，换工作区或 `/tmp` 再跑。

限制：

- **一次只派一个子代理，任务不可并行**：单分支线性历史，两个任务同时写同一棵树没有意义；后一个任务看到的是前一个已提交的结果。
- **无任务依赖**：不能声明「B 依赖 A 的产出」，只能人工安排顺序。
- **`ALLOW` 用逗号分隔**：路径本身含逗号无法表达。

## 何时用、何时不用

**用户明确要求派发时，直接派；明确要求不派时，不派。这两条优先于本节所有建议。用户没表态时，
父模型按下面的默认分工自主判断，不必逐次询问。**

默认分工：

| 情况 | 默认 |
|---|---|
| 会改文件、验收能机械核对、且需要迭代 | 派 |
| 评审（含只读 review，被审代码不改） | 要第二意见就派：交付 `findings.md`，用 `--allow-no-tests`，结论由父代理逐条核对；只为省 token 不派 |
| 查状态、读文件、跑一条命令看输出、网络探测 | 自己做 |
| 改一行、改配置、加个常量 | 自己做 |
| 选型、文案、架构取舍、调研 | 自己做 |
| 会改文件，但验收无法机械核对 | 可以派，但只能过滤结构；结论仍由父代理核对 |

**规模只看请求的措辞，不看代码**：单个表达式、常量、一行替换算小；新增函数、跨文件改动算需要迭代。
从请求看不出规模时，自己做——去勘察等于已经开工。用户明确要求派发时不受此限。
